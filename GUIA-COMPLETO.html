1
Instalar o Git no Windows
Só precisa fazer uma vez
1
Baixar e instalar o Git

Acesse git-scm.com → clique em "Download for Windows" → instale com todas as opções padrão (pode clicar Next em tudo).

💡 Dica: Na etapa "Default editor", selecione Visual Studio Code se já tiver instalado.
2
Configurar seu nome e e-mail no Git

Abra o Git Bash (aparece no menu iniciar após instalar) e execute:

# Substitua pelos seus dados do GitHub
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"

Isso identifica quem fez cada commit. Só precisa fazer uma vez.

2
Criar o repositório no GitHub
Onde o código vai ficar na nuvem
3
Criar o repositório

No GitHub, clique em "New repository" (botão verde no canto superior direito ou em github.com/new) e configure:

Nome: planilha-forex
Visibilidade: Public
☑ Add a README file: marcar essa opção
# O resto pode deixar padrão

Após criar, copie a URL do repositório. Ela será algo como:
https://github.com/seu-usuario/planilha-forex.git

3
Montar a pasta do projeto no PC
Os arquivos que você vai enviar pro GitHub
4
Criar a pasta e colocar os arquivos

Crie uma pasta em qualquer lugar do PC, por exemplo C:\projetos\planilha-forex\, e coloque esses arquivos dentro:

📁 planilha-forex/
  ├── Planilha_code_pro.html  ← a planilha
  ├── Dockerfile  ← diz ao Docker como empacotar
  ├── docker-compose.yml  ← configuração do container
  └── .gitignore  ← arquivos que o Git deve ignorar
💡 Os arquivos Dockerfile, docker-compose.yml e .gitignore foram gerados e estão disponíveis para download junto com este guia.
4
Enviar os arquivos para o GitHub (primeiro push)
Conectar a pasta local ao repositório remoto
5
Abrir o Git Bash dentro da pasta do projeto

Clique com o botão direito dentro da pasta planilha-forex no Windows Explorer e selecione "Git Bash Here". Um terminal vai abrir já posicionado na pasta correta.

6
Inicializar e enviar o código

Execute os comandos abaixo um por um no Git Bash:

# 1. Inicia o git nesta pasta
git init

# 2. Conecta ao seu repositório no GitHub
git remote add origin https://github.com/SEU-USUARIO/planilha-forex.git

# 3. Seleciona todos os arquivos para o commit
git add .

# 4. Cria o primeiro "save" com uma mensagem
git commit -m "primeiro commit: planilha forex"

# 5. Envia para o GitHub
git push -u origin main
⚠️ Na primeira vez, o Git vai pedir login do GitHub. Use seu usuário e senha (ou token de acesso pessoal se tiver autenticação em 2 fatores ativa).

Após isso, abra o GitHub no navegador e confirme que os arquivos apareceram no repositório.

5
Deploy no Portainer
Fazer o container subir a partir do GitHub
7
Criar uma nova Stack no Portainer

No Portainer, acesse: Stacks → Add Stack

Nome da stack: planilha-forex
Build method: Repository

Repository URL: https://github.com/SEU-USUARIO/planilha-forex
Repository reference: refs/heads/main
Compose path: docker-compose.yml
💡 Auto update: Você pode ativar o "Enable automatic updates" e definir um intervalo. Assim, sempre que você der push no GitHub, o Portainer atualiza o container automaticamente!
8
Clicar em Deploy the Stack

Clique no botão "Deploy the Stack" no final da página. O Portainer vai:

1. Clonar o repositório do GitHub
2. Ler o Dockerfile e o docker-compose.yml
3. Construir a imagem com o Nginx + seu HTML
4. Subir o container na porta 8080

Após alguns segundos, acesse: http://IP-DA-SUA-VPS:8080

🔄 Como atualizar a planilha no futuro

Após a configuração inicial, atualizar é simples. Basta editar o HTML no PC e executar 3 comandos:

edita o HTML
→
git add .
→
git commit -m "descrição"
→
git push
→
Portainer redesploya ✓

Se ativar o auto update no Portainer, o redesploy acontece automaticamente após o push!

📖 Glossário rápido

git initComeça a monitorar uma pasta com o Git
git add .Seleciona todos os arquivos modificados para o próximo commit
git commitRegistra um "save" do estado atual do projeto com uma mensagem
git pushEnvia os commits locais para o GitHub
git pullBaixa as mudanças do GitHub para o PC local
remoteO repositório remoto (no caso, o GitHub)
originApelido padrão para o repositório remoto principal
mainNome da branch (linha de desenvolvimento) principal
StackNo Portainer, é um grupo de containers definidos por um docker-compose.yml
DockerfileReceita que diz ao Docker como construir a imagem do container
